# Сервис управляемого редактирования 3D-моделей: как делать

Цель: править любую модель (голова, туловище, руки, ноги, предметы, здания, деревья) с помощью ИИ-инструмента, который
дообучается (а) с подкреплением и (б) на ручных правках пользователя. Пользователь управляет: выбирает область, цель,
ограничения и принимает или отклоняет каждое изменение.

## Принципы
1. Правка = операция (op), а не файл. Модель — исходник плюс журнал операций; любую можно отменить, переиграть, ветвить.
2. Инструмент = функция со схемой параметров (как `options.py`), областью действия (маска/часть), ценой и проверкой «до/после».
3. Критик = число, которое можно посчитать (как `eye_score`, `mesh_score`) плюс VLM-судья по рендерам. Критики — ограничения
   и награда, но решающее слово у человека.
4. Агент ничего не применяет молча: режимы «сам» / «предложи» / «только вручную».
5. Всё, что делает человек и агент, пишется в датасет (состояние, действие, исход, вердикт).

## Архитектура
- **Ingest.** glb/obj/gm → внутренний Asset: меши, UV, текстуры, скелет, семантические части. Части находит автосегментация
  по категории (голова: глаза/щёки/шея/ухо; здание: стена/крыша/дверь; дерево: ствол/крона), человек поправляет кистью.
- **Каталог операций.** Текстура: LaMa/диффузия-inpaint в UV, подгонка цвета, размытие. Сетка: заполнение ям
  (бигармоника, `smooth_pits`), сглаживание, децимация, ретопо. UV: подгонка (`fit_uv`). Форма: деформация клеткой/латтисом
  по маске. Материал/цвет. Замена части: image-to-3D (TRELLIS/Hunyuan3D-класс) с привязкой к границе. Каждая операция
  обратима и имеет `preview` в низком разрешении.
- **Критики.** Универсальные: осколки/растяжение/швы (`mesh_score`), симметрия, силуэт, бюджет полигонов/текстур, нет
  дыр и перевёрнутых граней. Категорийные: для головы — глаза (`eye_score`), для зданий — вертикали/проёмы, для деревьев —
  ветвление. Плюс VLM-судья «нравится ли, что не так» по ракурсам.
- **Агент.** VLM видит рендеры, метрики и цель текстом → предлагает последовательность операций → применяет в песочнице →
  смотрит критиков → откат/повтор. Лимит шагов и «бюджет изменений» (макс. смещение вершин, не трогать выбранные части).
- **Хранилище.** Версии = узлы дерева; ветка = вариант (сейчас это «Варианты головы»); рядом оценки и настройки.

## Как учится
1. **Лог демонстраций.** Ручная правка в режиме «учить»: снимок до/после, какой инструмент и параметры, маска. Это
   пары (состояние → действие) для имитационного обучения.
2. **Из ручных правок (SFT/LoRA).** (а) Политика выбора инструмента и параметров — небольшая модель-ранжировщик
   поверх планировщика. (б) LoRA для inpaint-модели на «до/после» текстур пользователя — перенимает его стиль.
   (в) LoRA для VLM-планировщика: (рендер, цель) → список операций.
3. **Предпочтения.** Экран «A или B» (сейчас сравнение двух голов рядом) даёт пары. Из них обучается reward-модель;
   затем DPO/GRPO по планировщику. Пары дешёвые и надёжнее абсолютных оценок.
4. **RL.** Среда = Asset + операции, награда = взвешенные критики + reward-модель по человеку, эпизод до принятия/лимита.
   Старт без нейросети: бандит по параметрам инструмента (например `NECKBLUR_SIGMA`, `PIT_RINGS`) — подбирает значения
   по оценке автоматически. Потом PPO/GRPO для последовательности операций.
5. **Против взлома награды.** Метрика сама не цель: оценка глаз 75 достигается и спрятав глаза. Поэтому держим отдельную
   отложенную выборку, периодически просим человека проверить, критики — ограничения, а не вся награда.
6. **Версии политик.** Новую политику выпускаем, только если она выигрывает у прежней на отложенных моделях по людям
   и метрикам; откат одной кнопкой.

## Прототипы (делать первыми, кликабельный HTML с выдуманными данными и подписями «как это работает»)
- **П1. Рабочая область.** Центр — 3D. Слева дерево частей (клик выделяет). Справа «Ассистент»: поле цели и карточки
  предложений: слайдер «до/после», изменение оценок, [принять] [отклонить] [подправить параметры]. Снизу лента правок
  с отменой и ветками.
- **П2. Область и инструмент.** Кисть/клик по модели → маска; выбор инструмента; параметры с живым превью; ограничения
  «не трогать», «макс. изменение».
- **П3. Сравнение A/B.** Две модели, камеры синхронны, кнопки «A лучше / B лучше / оба плохо» + причина — источник пар
  для reward-модели.
- **П4. Ручная правка и «учить».** Двигать вершины/красить; переключатель «учиться на этой правке»; список «что
  ассистент усвоил» с возможностью удалить неверное.
- **П5. Обучение.** Размер датасета, точность reward-модели, версии политики, сравнение на отложенных моделях, откат.

## Этапы
0. Прототипы П1–П5 и согласование. 1. Ядро: Asset + журнал операций, голова как первый набор инструментов (шаги
`headwrap.py` → операции). 2. Критики для категорий, общий формат метрик. 3. Агент-планировщик с VLM, режим
«предложи». 4. Лог демонстраций и ручной режим. 5. Reward-модель и DPO. 6. RL по параметрам, затем по последовательностям.
7. Новые категории (тело, предметы, здания, деревья) — каждая со своими частями и критиками.

## Что из текущего кода переиспользуется
`options.py` → схема параметров операций; `eye_score.py`/`mesh_score.py` → критики; варианты и сравнение → ветки и пары
предпочтений; `headwrap.py` шаги → операции; `shot.sh` → глаза ассистента для проверки интерфейса.

## Открытые вопросы
Какая категория вторая после головы; где считать (локально 5080 или облако для обучения); форматы на выходе (только glb
или ещё игровой `.gm`).
