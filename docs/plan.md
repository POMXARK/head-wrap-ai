# План: head-wrap-ai — голова по эталону с локальным ИИ

Дата: 2026-11-04. Статусы: ☐ не начато, ◐ в работе, ✔ сделано, ✘ тупик.

## 1. Зачем новый подход

Нынешний конвейер (corsairs-remake `tools/model3d`: Qwen 4 вида → TRELLIS/Pixal3D → чистка → UV → проекция →
head_auto) правит **сгенерированную сетку**. Оценщик сверяет её с 12 видами низкополигональной модели из игры.
Итог hv4: 64.37 → 65.25 баллов. Видимые дефекты остались, потому что:

- эталон формы — модель игры на ~1000 треугольников: глаз, ушей и губ в ней как формы нет, сверять детали не с чем;
- у сгенерированной сетки нет «смысла»: программа не знает, где веко, ухо, шея, губа. Части размечаются по цвету и
  положению (`parts.npy`), отсюда ошибки классов;
- UV собирается заново на каждой сетке: шов и острова каждый раз другие, текстуру нельзя ни переносить, ни учить;
- инструменты (hull, snap, relax, mirror) двигают вершины, но не умеют построить заново сломанную форму (ухо, веко).

Новый подход: брать **готовую правильную голову** с чистой топологией и постоянной UV-развёрткой (шаблон), обтягивать
её по сгенерированной (wrap), а текстуру запекать в UV шаблона. Тогда глаза, уши, губы и шея правильны по построению,
а локальный ИИ решает только то, что сетке не под силу: где кожа и где волосы, похоже ли на портрет, есть ли дефект.

## 2. Проблемы текущей модели (hero1, `glbcheck/hv4/auto.glb`, скриншоты пользователя 2026-11-04)

| # | Проблема | Что видно | Причина | Чем закрывается в плане |
|---|---|---|---|---|
| P1 | Глаз вогнут внутрь | глазница провалена, глазного яблока нет, веко рваное | TRELLIS делает глаз впадиной; в эталоне игры глаза как формы нет; relax/snap только сглаживают яму | шаблон с отдельными глазными яблоками и веками (этап 2), wrap не трогает глаз, ориентиры — уголки глаз (этап 3) |
| P2 | Шея раскрашена не той текстурой | на шее полосы цвета волос/камзола, переход кожа→одежда не там | проекция берёт пиксель вида, где шею закрывают волосы или воротник; классы кожи по цвету путают тень и волосы | маска частей из ИИ-сегментации видов (этап 5), запекание только из видов, где шея видна (этап 4) |
| P3 | Грязный хвост | на волосах хвоста пятна кожи и фона | хвост — отдельная тонкая лента в сетке, на неё проецируются кожа шеи и фон; `skin_to_hair` красит только найденные пятна | хвост как отдельная деталь шаблона (карточки/трубка), текстура волос из сегментации, без кожи (этапы 2, 5) |
| P4 | Текстура губ не на месте | красный цвет губ сдвинут на подбородок/щёку | форма рта сетки не совпадает с ртом на видах (optical flow выравнивает только частично) | ориентиры уголков рта на видах и на шаблоне (этап 3), UV губ шаблона постоянна → запекание по ориентирам |
| P5 | Сломанные уши | ухо — плоский лист с дырами и шипами, нет завитка | TRELLIS не строит тонкие формы; mirror копирует уже плохое ухо | ухо берётся из шаблона целиком, wrap двигает его только как целое (поворот, масштаб) (этап 3) |
| P6 | Рваная ноздря | край ноздри зубчатый, складки | шумная поверхность сетки около носа | топология носа шаблона, wrap со сглаживанием (этап 3) |
| P7 | Складки и выпуклости волос | bulge 1.02 %, folds 1441 | генерация, relax снимает частично | волосы — отдельный слой (оболочка поверх черепа шаблона) (этап 2) |
| P8 | 8 промежуточных видов без Qwen | эталон силуэта только в 4 видах | Qwen делает 4 вида | ИИ-судья по рендерам любых ракурсов (этап 6) |
| P9 | Оценщик «не умный» | баллы растут, а глаз и ухо остаются сломанными | метрики силуэта/цвета не видят смысловых дефектов | ИИ-судья (VLM) + обучаемый классификатор дефектов (этапы 6, 7) |
| P10 | UV каждый раз новая | текстуры разных прогонов не сравнить и не учить | автo-UV на каждой сетке | постоянная UV шаблона (этап 2) |

## 4. Этапы работ

### Этап 0. Каркас программы ✔
- `app.py` — один файл на stdlib по образцу diskview: сервер `127.0.0.1:8770`, страницы «Модель», «Шаблон», «Виды»,
  «ИИ», «Журнал»; конфиг `~/.head-wrap-ai/config.json`; профили моделей (Ollama на ПК через ssh-туннель или адрес,
  OpenAI-совместимый локальный); кнопка «Проверить» (`/api/tags`, пробный запрос).
- Логи в панели и в `work/log.txt`; кэш ответов ИИ `work/cache/` по sha1 (картинка + промпт + модель).
- Приватность: по умолчанию только `127.0.0.1`/LAN; внешний адрес — предупреждение; картинки наружу не уходят.
- Готово, когда: `python app.py` открывает страницу, «Проверить» показывает список моделей Ollama.

### Этап 1. Шаблон головы с UV ◐
- Вырезать из `base.obj` голову и шею **с UV** (по группе `body` и плоскости под ключицами), отдельно глазные яблоки,
  веки/ресницы, зубы; сохранить `template/head.obj` + `template/regions.json` (кожа лица, шея, уши, губы, глаза,
  скальп, нос) — регионы по UV-островам и по положению, один раз, проверка картинкой.
- Ориентиры шаблона (≈ 30): уголки глаз, крылья носа, кончик носа, уголки рта, верх/низ уха, подбородок, ямка шеи.
- Готово, когда: рендер шаблона спереди/сбоку + развёртка с раскрашенными регионами.

### Этап 2. Волосы и хвост как отдельный слой ☐
- Скальп шаблона → оболочка волос, сдвинутая по нормали до поверхности сгенерированной головы (там, где сегментация
  говорит «волосы»); хвост — трубка по осевой линии, найденной в сгенерированной сетке.
- Своя UV волос (полосы вдоль роста), текстура только из пикселей класса «волосы».
- Закрывает P3, P7.

### Этап 3. Обтяжка (wrap) шаблона по сгенерированной голове ◐
- Грубо: выравнивание по ориентирам (Procrustes: поворот, масштаб, сдвиг).
- Ориентиры на цели: по 4 видам Qwen (детектор лица на картинках → луч в сетку) и/или ручная расстановка кликами в UI.
- Тонко: `nricp_amberg` от жёсткого к мягкому, веса: кожа лица и шея — тянутся к цели; глаза, уши — только как целое
  (жёсткое движение по своим ориентирам); волосы цели не участвуют (под ними скальп шаблона).
- Проверка: расстояние до цели, нет самопересечений, глаз выпуклый (нормаль глазного яблока наружу), сравнение 12
  ракурсов `head_views`.
- Закрывает P1, P5, P6 по форме.

### Этап 4. Запекание текстуры в UV шаблона ◐
- Для каждого текселя UV шаблона — точка на поверхности → лучший вид (угол к камере, видимость по z-буферу, класс
  пикселя совпадает с регионом текселя: шея берёт только «кожа», волосы только «волосы»).
- Ориентиры выравнивают картинку вида по рендеру (губы, глаза на месте) — warp по треугольникам ориентиров.
- Дыры (за ухом, под подбородком) — заливка из соседних текселей того же региона, потом ИИ-инпейнтинг (этап 5).
- Закрывает P2, P4, P10.

### Этап 5. Локальный ИИ: сегментация и инпейнтинг ☐
- Сегментация видов на классы кожа / волосы / губы / глаза / брови / уши / шея / одежда / фон. Варианты по порядку:
  (а) face-parsing модель со свободной лицензией на ПК (проверить лицензию до использования),
  (б) VLM `ministral-3:14b` даёт рамки и подписи → уточнение по цвету,
  (в) ручная кисть в UI. Результат кэшируется, правка руками помечается «вручную».
- Инпейнтинг дыр текстуры через ComfyUI на ПК (workflow с маской), только регион, только локально.

### Этап 6. ИИ-судья ◐
- Рендер 12 ракурсов + крупные планы (глаз, ухо, рот, хвост, шея) → VLM `ministral-3:14b` с вопросом «какие дефекты:
  вогнутый глаз, рваное ухо, кожа на волосах, губы не на месте…» → JSON {дефект, место, уверенность}.
- Судья не правит сам: его ответ — задача для инструмента (этап 7) и пункт в журнале.
- Сверка судьи с метриками (выпуклость глаза, класс пикселей) — расхождения в журнал.
- Закрывает P8, P9.

### Этап 7. Обучение на правках ☐
- Каждая правка (авто 🤖 или ручная) пишется в `work/feedback.jsonl`: что было, что сделано, принято/отменено, оценка
  судьи до/после, ручная оценка пользователя (👍/👎).
- Из этого учится: (а) политика выбора инструмента (бандит, как `head_policy.json`); (б) маленький классификатор
  дефектов по эмбеддингам крупных планов (`bge-m3`/`nomic-embed-text` не для картинок — взять визуальные эмбеддинги
  VLM или CLIP со свободной лицензией) — чтобы судья ошибался реже; (в) поправки ориентиров: ручные клики становятся
  обучающими примерами детектора ориентиров.
- Дообучение весов больших моделей — не в первой версии; сначала журнал и простые модели.

### Этап 8. Экспорт и проверка в игре ☐
- `out/<model>.glb` + текстура → конвертеры corsairs-remake → `pdm-game`; кадр в движке.
- Сравнение до/после в UI (12 ракурсов рядом).

## 5. Правила проекта
- Только локальные модели (ПК пользователя и LAN). Облачные модели (`*-cloud`) и внешние API — выключены, включение
  только явно с предупреждением.
- Шаблоны и модели — только со свободной лицензией, автор и лицензия в `CREDITS.md`.
- Ресурсы игры Akella в репозиторий не кладутся; код Akella не копируется.
- Каждая находка, тупик и результат проверки — сюда, в раздел «Журнал этапов».

Хвост шаблоном не покрывается (так и надо — отдельный слой, этап 2). **Проблемы первой версии**: кольца вокруг глаз (веки шаблона растянуты к яме глаза цели — P1 переносится в шаблон) и сжатый рот; нужны ориентиры и жёсткие веса для глаз/ушей (по плану), плюс проверка самопересечений. Эти зоны — следующий шаг.
- 2026-11-04: `wrap_fit.py` — свободные зоны (веки в радиусе 0.55 вокруг центров глаз, уши): вершины не тянутся к цели, их смещение — гладкое среднее смещений соседей (300 итераций); `nricp_amberg` в trimesh 4.3.2 не принимает веса вершин (проверено по сигнатуре; `nricp_sumner` тоже), поэтому веса сделаны постобработкой. Результат: глаза круглые, уши целые (P1, P5 по форме закрыты в шаблоне), расстояние до цели в среднем 0.0111 (выросло намеренно: в глазах и ушах цель — яма и плоский лист), 458 вершин >0.03. Осталось: рот сжат/смещён вниз к подбородку (нужны ориентиры уголков рта), проверка самопересечений, глазные шары (eyes.obj) ещё не перенесены вместе с головой, шея нижним краем плоская.
- 2026-11-04: этап 4, первая версия — `bake.py`: тексель UV шаблона → точка на обтянутой голове → ближайшая точка цели → цвет её текстуры (1024², 221k текселей, ~мин). Атлас читается: лицо, оба уха целые с текстурой, шея кожей, волосы на скальпе без пятен кожи, борода на месте. Замечено: рот — тёмная щель без розовых губ (рот шаблона сжат, см. выше), внутренние острова глаз/рта грязные (кожа вместо белка/зубов — берутся из головы-цели, где их нет). Не сделано: лучший вид на тексель, классы регионов, заливка дыр, 3D-проверка рендером с текстурой.
- 2026-11-04: `render.py` (плоский текстурированный рендер matplotlib: анфас, 3/4, профиль) — голова узнаваема, уши целые с завитком, шея кожей, на волосах нет пятен кожи и грязного хвоста, борода и лицо на месте; видны: нет глазных шаров (в глазницах дыры), рот плоский. Рендер — низкая детализация (цвет на грань), для проверки формы и регионов, не для просмотра качества текстуры.
- 2026-11-04: `judge.py` (VLM-судья через профиль app.py, ministral-3:14b) — **тупик первой версии**: перечисление категорий в промпте («eyes, ears, neck…») заставляет модель выдать дефект в каждой категории (12 дефектов, severity 3–5, overall 3) даже на голове, где уши целые, а хвоста нет. Судью нельзя спрашивать «какие дефекты у …».
