# Промт: автономная работа по docs/tasks.md

Вставлять в начало сессии Claude Code в этом проекте.

```
Работай по docs/tasks.md автономно, одним заходом, до конца списка.

Цикл на каждый пункт:
1. Прочитай пункт и соседний код (grep/Read), ничего не предполагай.
2. Сделай правку.
3. Прогони тест пункта (cd tests && python3 <файл>). Если упал, чини и повторяй.
4. Для интерфейса проверь в видимом окне Chrome реальной мышью (xdotool),
   сними кадр и посмотри его. Тест API одного недостаточно.
5. Обнови docs/tasks.md (статус, что проверено) и docs/ux-review.md,
   если менялся интерфейс.
6. Закоммить (английский, формат: feat:/fix:, пункты "файл — что — почему",
   блок Tests:, Co-Authored-By) и запушь в origin main.
7. Сразу переходи к следующему пункту.

Правила:
- Не останавливайся для отчёта и не жди подтверждения. Между пунктами
  пиши одну строку «что делаю».
- Спрашивай только если без ответа продолжить нельзя: выбор между разными
  архитектурами, доступ или ввод, который есть только у меня.
  Остальное решай по самому очевидному варианту и отмечай в docs/tasks.md.
- Ошибки сборки и тестов чини сам. Блокер (классификатор отклонил команду и т. п.)
  не обходи: пропусти пункт, запиши причину в docs/tasks.md и иди дальше.
- Не делай два пункта в одном коммите. Изменения применяй отдельными вызовами,
  чтобы упавший тест не скрывал правки.
- Новая функция получает свой тест. Существующие тесты не расширяй.
- Закрыто только если тест зелёный, кадр показывает ожидаемое и в логах нет ошибок.
- Тяжёлое (обучение, долгие запуски) запускай в фоне и жди уведомления.
- Приложение и окна Chrome закрывай в конце или когда я скажу.

Итог пиши один раз в конце: что сделано, что проверено (тесты и кадры),
что заблокировано и почему, что дальше.

Начни с первого незакрытого пункта.
```
